# Deployment conformance target contract

`scripts/conformance.sh` accepts only public endpoints, a test PAT, optional SSH client
material, and opaque operator hooks. It does not know which provider hosts the target.

The repository named by `ADENOSINE_CONFORMANCE_OWNER` and
`ADENOSINE_CONFORMANCE_REPOSITORY` must already exist, be public, and be writable by the
PAT. The runner creates unique refs and removes them on exit; it does not delete the
repository. SSH runs only when host, private key, and pinned known-hosts file are all set.

Capabilities are explicit. A `custom` target may omit capabilities and receives visible
skips. An official target must declare and configure every mandatory capability; missing SSH,
telemetry, backup/restore, public web routing, or immutable build identity fails the run.
`build-identity` compares the gateway's `X-Adenosine-Image-Digest` response header with the
configured immutable digest.

Backup/restore hooks are deliberately commands rather than provider definitions. A backup
hook writes an identifier to `$BACKUP_ID_FILE`; the restore hook receives `BACKUP_ID` and
must restore PostgreSQL, `/var/lib/adenosine`, the SSH host key, and application secrets into
a clean target. Telemetry hooks query an operator-controlled collector and must return zero
after observing traffic generated by this run. Hooks must never print secrets.
The runner pushes a unique fixture ref before backup and verifies the same commit after clean
restore, then removes it during cleanup.
