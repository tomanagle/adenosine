# Adenosine v0.1.0

This is the first public-alpha release candidate. It provides immutable Linux amd64/arm64 images,
Linux and macOS binaries, a generated TypeScript API client, OpenAPI, checksums, and SPDX SBOMs.

## Deployment and migration

New self-hosted installations must follow [`../self-hosting.md`](../self-hosting.md). Existing
development Compose volumes are not a supported production migration source. Production startup
does not apply migrations automatically; run `scripts/migrate.sh` before starting this image.

All migrations included in v0.1.0 are forward-only. There is no earlier production release to roll
back to. Preserve a verified maintenance-window backup before applying later releases.

## Demonstration status

The repository includes two-instance federation acceptance automation, ordinary smart HTTP/SSH Git
coverage, and production Compose backup/clean-restore coverage. These automated tests are not the
live portable-DID proof. Release publication requires approval of the protected
`portable-did-release-proof` GitHub environment and `ADENOSINE_PORTABLE_DID_PROOF_URL` to reference
a JSON artifact for this tag recording two independent instances, two portable-DID users, ordinary
Git success, deployment conformance, production backup/restore, and a public evidence URL. The workflow validates and attaches that artifact rather
than claiming the local federation fixture is equivalent evidence.

## Known limitations

- Public alpha; no high-availability or zero-downtime upgrade guarantee
- Full backups require a maintenance window; no incremental backup or PITR
- Electric and Tap are optional and their rebuildable caches are not in portable backups
- Operators must provide encrypted off-host retention and backup authenticity signatures
- No LFS, private federation, enterprise SSO, custom Git storage, or Kubernetes support
